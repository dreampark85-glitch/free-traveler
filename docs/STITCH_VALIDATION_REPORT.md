- **검증 방식**: 기존 프로젝트 재조회 → 화면별 canonical(대표) 스크린 1건 선정 → HTML 콘텐츠를 직접 페치하여 Section 계약/콘텐츠 요건 확인 → NEEDS_REVISION 항목만 `edit_screens`(제자리 수정)로 최소 보정. 신규 화면 생성(`generate_screen_from_text`)은 사용하지 않았으며, 검증 과정에서 새 중복 화면을 만들지 않았다(SCR-005 보정 1건은 edit_screens의 사양상 새 스크린 ID로 저장되나, 이는 "최소 수정"의 산출물이며 무작위 재생성이 아님).

## 사전 확인 사항

- 프로젝트에는 이전 세션의 반복 타임아웃-지연성공 패턴으로 인해 화면별로 다수의 중복 스크린이 존재한다(SCR-002 2건, SCR-004 3~4건, SCR-005 기존 5건, SCR-001 Mobile 4건, SCR-003 Mobile 5건 등). 본 검증에서는 각 화면마다 콘텐츠가 가장 완전한 1건을 **canonical 스크린**으로 선정하여 검증했다. Stitch API에는 스크린 삭제 기능이 없어 나머지 중복은 프로젝트에 그대로 남아있다 — Stitch 웹 UI에서 수동 정리가 필요하다(누락 항목에 기재).
