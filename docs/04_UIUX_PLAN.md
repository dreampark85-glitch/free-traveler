# UI/UX Plan — Free Traveler

- **Document ID:** UIUX-TRAVEL-001
- **기반 문서:** `01_PRD.md`, `02_SRS_BASELINE.md`, `PROJECT_SCOPE.md`, `03_UI_COVERAGE_ANALYSIS.md`
- **참고(스타일 레퍼런스, 상표 요소 미사용):** `design-reference/vendor/airbnb/DESIGN.md`
- **대상 화면:** SCR-001 `/`, SCR-002 `/about`, SCR-003 `/travel-tools`, SCR-004 `/mates`, SCR-005 `/account`

> Airbnb 레퍼런스는 "사진 중심의 넉넉한 여백 + 단일 포인트 컬러 + 부드러운 라운드"라는 **레이아웃 철학**만 참고한다. Airbnb 워드마크, Cereal 서체, Rausch(#ff385c) 정확한 색상값, 하트 저장 아이콘 등 상표적 요소는 그대로 사용하지 않고 Free Traveler 고유 토큰으로 재정의한다.

---

## 1. 브랜드와 디자인 원칙

| 원칙 | 내용 |
|---|---|
| 브랜드명 | **Free Traveler** |
| 톤 | 신뢰할 수 있는 여행 준비 허브 — 사진과 정보 밀도를 함께 존중하되, 광고성 문구·과장된 슬로건을 쓰지 않는다 |
| 배경 | 흰 배경(Canvas)을 기본으로 하고, Section 구분에는 옅은 웜그레이 Surface만 사용한다(그림자·다크 섹션 남용 금지) |
| 텍스트 | 짙은 회색(Ink) 위주, 순수 검정(#000)은 사용하지 않는다 |
| 포인트 컬러 | 코랄(Coral) 단일 포인트 — 버튼, 활성 탭, 링크, 강조 배지에만 제한적으로 사용 |
| 경고·안전 | 코랄과 색상 축이 분명히 다른 semantic color(호박색 경고, 적색 위험, 청색 정보)를 사용해 "일반 강조"와 "위험 신호"를 혼동하지 않게 한다 |
| 서체 | 한글 본문은 Inter + 시스템 한글 폰트 fallback |
| 접근성 | 모든 인터랙션 요소 키보드 포커스 링 확보, 터치 영역 44×44px 이상 |
| 콘텐츠 | 더미 텍스트와 미완성을 드러내는 자리표시 문구를 쓰지 않고, 데이터가 없을 때도 완결된 한국어 문장 + 다음 행동 CTA로 채운다 |

## 4. 재사용 Section 패턴

5개 화면이 "같은 Card만 반복"하지 않도록 아래 6개 패턴을 교차 사용한다. 화면별 배치는 5~9장에서 패턴명으로 표기한다.

| 패턴 | 구조 | 비고 |
|---|---|---|
| **Hero** | 헤드라인 + 1~2문장 설명 + Primary/Secondary CTA (+ 검색 입력) | 뷰포트 전체 높이 금지, 다음 Section 시작이 보여야 함 |
| **Card Grid** | 제목+설명 + N개 Card(이미지/아이콘, 제목, 메타, 태그) | Desktop 3~4열 · Mobile 1열 |
| **좌우 분할(Split)** | 좌: 텍스트/폼/목록, 우: 이미지·요약·상세 패널 | Mobile은 세로 스택(상→하) 또는 목록→Drawer 전환에 사용 |
| **Chip 목록** | 가로 스크롤/랩 Chip 그룹, 각 Chip은 필터·태그 역할 | 44px 이상 터치 영역, 선택 시 코랄 배경 |
| **3단계 안내** | 번호+아이콘+제목+1문장 설명 3개(가로, Mobile은 세로 스택) | 이용 순서·신청 절차 설명에 사용 |
| **CTA Banner** | 코랄 틴트 배경 + 헤드라인 + 설명 + 버튼 1~2개 | 화면 하단부에 배치해 다음 행동 유도 |

## 5. SCR-001 `/` 메인

**사용자 목표:** 국내·해외 여행지를 탐색하고, 안전정보와 대표 소개까지 한 화면 흐름에서 확인한 뒤 `/travel-tools`·`/mates`로 이동한다.

### 5.1 Section 구성 (7개)

| # | 제목(예시) | 패턴 | 콘텐츠 | 이동/CTA | 관련 요구사항 |
|---|---|---|---|---|---|
| 1 | 어디로 떠날지 정해볼까요? | Hero | 헤드라인 1줄 + 설명 1문장 + 여행지 검색창(키워드) + `/travel-tools` 보조 CTA("여행 조건부터 정리하기") | 검색 제출 시 3번 이하로 스크롤·필터 반영, 보조 CTA → `/travel-tools` | REQ-FUNC-002/003/067 |
| 2 | 국내에서 다시 발견하는 여행지 | Card Grid(6) | 서울·부산·제주 등 국내 인기 여행지 6개 카드(대표 이미지+alt, 지역명, 테마 태그, 추천 기간) | 카드 선택 → 동일 화면 상세 Drawer 오픈 | REQ-FUNC-001/002/004/007/009 |

| 4 | 어떤 이유로 떠나고 싶으신가요? | Chip 목록(6) | 휴양·미식·액티비티·문화·가족여행·나 홀로 여행 등 테마 Chip 6개 | Chip 클릭 → 2·3번 Card Grid 필터링(같은 화면 내 스크롤 이동) | REQ-FUNC-002 |
| 5 | 떠나기 전 꼭 확인할 안전정보 | Card Grid(6) | 소개 국가 중 6개 국가 안전정보 요약 카드(경보 단계 텍스트 라벨, 최종 확인일) | 카드 선택 → 안전정보 Drawer(8개 카테고리, 출처, stale 배지) | REQ-FUNC-006/047~054 |
| 6 | 함께 떠날 동행을 찾고 있어요 | 좌우 분할 | 좌: "동행과 함께라면" 소개 문장 + `/mates` 이동 CTA. 우: 모집중 동행글 3개 카드(제목·국가·기간·모집 인원) | 카드/CTA → `/mates`; 데이터 0건이면 Empty 상태(6.2 참고) | REQ-FUNC-030/033 |
| 7 | free_traveler가 소개하는 이유 | CTA Banner | 대표 사진(원형) + 소개 한 줄 + `50+ Trips` · `30+ Countries` 배지 + `/about` CTA | → `/about` | REQ-FUNC-057 |

### 5.2 상태 정의

| 상태 | 적용 Section | 내용 |
|---|---|---|
| Loading | 2·3·5번(초기 렌더 중 스켈레톤 카드), 상세/안전정보 Drawer 오픈 시 | 카드 형태의 스켈레톤(제목 바 + 이미지 블록)만 표시, 문구 없음 |
| Success | 전체 | 정적 데이터 기반이므로 기본 상태 |
| Empty | 6번 | "아직 모집중인 동행글이 없어요. 새 동행글을 가장 먼저 올려보세요." + 이용 방법 1문장 + "동행글 작성하기" CTA(`/travel-tools` 동행 탭) |
| Error | 5·6번 Drawer 로드 실패, 검색 실패 | "정보를 불러오지 못했습니다. 다시 시도해 주세요." + 재시도 버튼(색상: `color.danger` 텍스트, 배경은 `color.danger-bg`) |
| Unauthorized | 해당 없음 | SCR-001은 전체 공개 화면 |

### 5.3 Drawer/Modal 사양

- 여행지 상세, 안전정보 상세는 **같은 화면(SCR-001) 위 Drawer**로 연다(별도 라우트 없음).
- Desktop(1440px): 화면 우측에서 슬라이드인, 폭 480~560px, 배경 스크림 `rgba(36,35,39,.4)`.
- Mobile(390px): 하단에서 슬라이드업하는 풀스크린 Drawer, 상단 고정 닫기 버튼(44×44px).
- 여행지 Drawer 하단에 "이 국가 안전정보 보기" 링크 → 같은 Drawer 스택에 안전정보 패널을 push(뒤로가기로 복귀).

## 6. SCR-002 `/about` 대표 소개

**사용자 목표:** `free_traveler`의 여행 경력과 편집 기준을 확인해 콘텐츠 신뢰도를 판단한다.

### 6.1 Section 구성 (7개)

| # | 제목(예시) | 패턴 | 콘텐츠 | 이동/CTA | 관련 요구사항 |
|---|---|---|---|---|---|

## 9. SCR-005 `/account` 계정·관리

**사용자 목표:** 로그인하고 프로필·활동을 관리하며, 관리자 권한이 있으면 신고 상태와 외부 URL을 관리한다. **역할에 없는 탭은 렌더링하지 않는다.** Dashboard형 통계 화면은 만들지 않는다.

### 9.1 공통 구조

- 상단 Intro: "계정을 관리하고 내 활동을 확인하세요" 1문장 + 현재 로그인 상태 배지.
- 탭 바(Tab 스위처): 로그인 여부·역할에 따라 탭이 동적으로 구성된다.

| 역할 | 렌더링되는 탭 |
|---|---|
| Guest(비로그인) | 로그인/가입 |
| Adult Member | 프로필 · 내 활동 |
| Moderator/Admin | 프로필 · 내 활동 · 관리자 |

### 9.2 Guest 탭: 로그인/가입

## 11. 접근성·인터랙션 공통 규칙

- 모든 버튼·링크·Chip·탭의 실제 터치 영역은 최소 **44×44px**을 확보한다(시각적 크기가 작아도 히트 영역을 패딩으로 확장).
- 키보드 포커스는 `outline: 2px solid color.coral; outline-offset: 2px`로 전 컴포넌트에 통일 적용한다.
- Drawer/Modal은 열릴 때 포커스를 내부 첫 상호작용 요소로 이동시키고, `Esc` 및 배경 클릭으로 닫히며 닫힌 후 포커스는 트리거 요소로 복귀한다.
- 경고·오류·안전 배지는 색상 단독이 아닌 아이콘 + 텍스트 라벨(예: "⚠ 재확인 필요", "🚫 여행유의")을 함께 표시한다.
- 이미지 alt 텍스트는 "여행지/사진 명"이 아니라 실제 장면을 설명하는 문장으로 작성한다(예: "저녁 노을이 물든 산토리니 해안 마을 전경" 형태 — 실제 소재는 콘텐츠 데이터 작성 시 확정).
